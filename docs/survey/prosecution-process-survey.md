# 출원 프로세스 설문조사 추진안

> 출원담당자·발명자·심의위원을 대상으로 설문을 실시하여 **개별 인터뷰와 Data 분석만으로 확인하기 어려운 실제 업무경험과 제도 인식**을 폭넓게 확인하고, 참여주체 간 인식 차이와 이상징후를 감사 현안 검증에 활용한다.

## 1. 추진 배경

출원 프로세스 감사는 Data 분석, 인터뷰, 개별 Case 검증을 통해 현안 가설을 도출할 수 있으나, 일부 사례가 특정 개인의 경험인지 조직 전반에서 반복되는 구조적 현상인지 판단하기에는 한계가 있다.

따라서 설문조사는 다음 두 가지 목적으로 활용한다.

1. **현안 가설의 확산성 확인**  
   인터뷰·Case에서 확인된 현상이 다수 참여자에게도 반복되는지 정량적으로 확인한다.
2. **참여주체 간 인식 Gap 및 신규 현안 탐색**  
   동일 Process를 경험하는 출원담당자·발명자·심의위원의 인식 차이를 비교하여 잠재 취약영역을 식별한다.

!!! note "설문조사의 역할"
    설문결과만으로 현안을 확정하지 않는다. 설문은 **이상징후 Screening 수단**으로 활용하고, Data·인터뷰·원본 Case를 추가 확인하여 최종 현안 여부를 판단한다.

## 2. 감사 접근에서 설문의 위치

```text
Data 분석 ──────┐
인터뷰 ─────────┼──→ 현안 가설 도출
Case 검증 ──────┘
                       ↓
                 [ 설문조사 ]
          다수 참여자의 실제 경험·인식 확인
                       ↓
           가설의 확산성 + 신규 현안 탐색
                       ↓
             추가 Data / Case 거증
                       ↓
                  감사 현안
```

핵심은 **“일부 사례에서 확인된 현상이 특정 개인의 경험인지, 조직 전반에서 반복되는 구조적 현상인지 확인”**하는 것이다.

## 3. 설문 대상 및 확인영역

설문 대상은 출원 프로세스에서 서로 다른 역할을 수행하는 **출원담당자, 발명자, 심의위원**으로 구분한다. 세 집단에 동일한 질문을 일률적으로 적용하기보다 각자의 실제 경험과 역할에 맞는 문항을 구성하되, 동일 Process에 대한 인식 차이를 비교할 수 있는 공통·대응 문항을 포함한다.

| 설문대상 | 주요 경험 구간 | 주요 확인영역 |
|---|---|---|
| **출원담당자** | 발명접수 → 명세서 → 출원/OA | 업무부담, 발명자 협업, 대리인 관리, 명세서·Claim 품질관리 |
| **발명자** | 발명신고 → 명세서 검토 → 권리화 | 출원지원, Claim 검토 참여, 변경내용 인지, 담당자·대리인 지원 |
| **심의위원** | 발명평가 → 등급 결정 | 평가기준 명확성, 위원 전문성, 검토시간, 공정성·독립성 |

### 대상 선정 원칙

세부 표본 추출 Logic은 별도 정비된 기준을 적용하되, 다음 관점을 유지한다.

- 특정 조직·기술분야·기간에 편중되지 않도록 표본 구성
- 출원 경험 및 심의 경험이 실제로 존재하는 대상 중심
- 필요 시 고등급/일반등급, 다출원/일반 발명자 등 비교집단 구성
- 응답자의 익명성·비밀성을 고려하여 개인 평가 목적이 아닌 Process 진단임을 명확히 안내

## 4. 설문 분석 Logic

```text
                    [ 설문 응답 ]
                         ↓
          ┌──────────────┼──────────────┐
          ↓              ↓              ↓
      전체 응답       집단별 비교      이상응답
       Trend           Gap 분석         탐색
          │              │              │
          │      출원담당자 ↔ 발명자     │
          │        발명자 ↔ 심의위원      │
          └──────────────┼──────────────┘
                         ↓
                    현안 후보 도출
                         ↓
              Data / 인터뷰 / Case 거증
                         ↓
                    감사 현안 판단
```

### 참여주체 간 Gap 분석 예시

동일 Process에 대해 관점을 달리한 대응문항을 설계한다.

- 출원담당자: “발명자가 Claim 검토에 충분히 참여한다.”
- 발명자: “Claim의 주요 변경내용을 충분히 설명받고 검토한다.”

두 집단의 긍정응답률에 큰 차이가 발생하면, 단순 만족도 차이가 아니라 **제도와 실제 운영 간 괴리 가능성**으로 보고 추가 거증한다.

## 5. 설문결과 → 감사검증 Matrix

| 설문에서 나타난 이상징후 | 추가 거증 | 연결 가능한 현안 |
|---|---|---|
| 발명자의 Claim 변경 인지도가 낮음 | OA 변경이력·발명자 승인기록 | OA 대응 시 발명자 참여 미흡 |
| 심의위원의 평가기준 명확성 응답이 낮음 | 위원별 점수편차·등급변경 이력 | 등급평가 일관성 미흡 |
| 출원담당자별 업무부담 편차가 큼 | 담당자별 처리건수·Lead Time·OA | 업무량에 따른 검토품질 편차 |
| 대리인 품질 만족도 편차가 큼 | 대리인별 OA·Claim 변화·배정현황 | 대리인 배정·품질관리 |
| 참여주체 간 동일항목 인식 Gap이 큼 | 인터뷰·표본 Case | 제도와 실제 운영 간 괴리 |
| 심의의 독립성·공정성 관련 이상응답 | 발명자-심의위원 Mapping, 심의 History | 이해상충 통제 미흡 가능성 |

## 6. 최종 활용방안

설문조사는 단순 만족도 조사가 아니라 **사람·Process 측면의 이상징후 Screening**으로 활용한다.

- **AI 특허 분석**: 특허 Data에서 기술 차별성·권리 실효성·기술 영향력 이상징후 Screening
- **설문조사**: 참여주체의 경험·인식에서 Process 이상징후 Screening
- **기술전문가/인터뷰/Case 검증**: Screening 결과의 실제 원인 및 구조적 문제 여부 검증
- **감사 현안**: 개별 사례가 아닌 반복 가능한 Process·통제 문제로 구조화

> **AI는 특허 자체의 이상징후를, 설문은 사람과 Process의 이상징후를 폭넓게 탐색하고, 양쪽 결과를 Data·인터뷰·Case로 교차검증한다.**

## 7. 보고용 장표 구성

### 대제목
**출원 프로세스 참여주체 대상 설문을 통한 제도 운영 실태 및 잠재 현안 진단**

### 중제목 ①
**인터뷰·데이터 분석만으로 확인하기 어려운 실제 업무경험과 제도 인식을 참여주체별 설문을 통해 폭넓게 확인**

- 개별 인터뷰 중심 확인의 대표성 한계를 보완하고 출원 프로세스 전반의 공통 경험을 정량적으로 확인
- 출원담당자·발명자·심의위원의 역할별 관점 차이를 비교하여 프로세스 단계별 잠재 취약영역 식별

### 중제목 ②
**설문결과를 참여주체·프로세스별로 교차분석하여 이상징후를 식별하고 Data·인터뷰를 통한 현안 검증으로 연계**

- 동일 Process에 대한 참여주체 간 응답 차이와 특정 집단의 이상응답을 분석하여 현안 후보군 도출
- 설문결과를 단독 판단근거로 활용하지 않고 특허 Data·인터뷰·Case 검증과 결합하여 최종 현안 여부 판단
